# Как работать с проектом

## Начало

```bash
nvm use            # версия Node берётся из .nvmrc
npm install        # заодно ставит хуки git
npm run dev
```

## Перед коммитом

Хуки сами форматируют и проверяют изменённые файлы. Всё сразу (как в CI):

```bash
npm run check      # форматирование, ESLint, stylelint, типы, тесты с порогом 100%, сборка
npm run test:e2e   # сквозные тесты (нужны браузеры: npx playwright install chromium firefox webkit)
```

## Правила

- **Строгий TypeScript.** Без `any`, без `!`. Если проверка кажется лишней, а компилятор её требует,
  значит, тип можно уточнить.
- **Тесты вместе с кодом.** Порог покрытия 100%: непокрытый код не пройдёт CI. Недостижимую проверку
  удаляйте, а не прячьте от отчёта.
- **Доступность.** Нативные элементы (`button`, `a`, `input`), у иконок-кнопок `aria-label`, цвет не единственный носитель смысла.
  Новые экраны проверяет axe в e2e.
- **Стили.** Цвета только из токенов (`tokens.css`). Каждый компонент — в своём файле `src/styles/`.
  Анимируйте `transform` и `opacity`; уважайте `prefers-reduced-motion`.
- **Безопасность.** Не добавляйте `innerHTML`, встроенные скрипты и внешние запросы (CSP их запретит).
  Адреса из данных пропускайте через `safeExternalUrl`.
- **Данные.** Меняйте `data/bloggers.csv` и запускайте `npm run data`; JSON руками не правится.

## Полезные команды

| Команда                  | Зачем                                                 |
| ------------------------ | ----------------------------------------------------- |
| `npm run coverage`       | Тесты с отчётом и порогом 100%                        |
| `npm run mutation`       | Мутационные тесты логики (около 15 минут)             |
| `npm run test:visual`    | Скриншотные тесты (обновить: `-- --update-snapshots`) |
| `npm run size`           | Бюджет размера сборки (после `npm run build`)         |
| `npm run licenses`       | Проверка лицензий зависимостей                        |
| `npm run licenses:write` | Обновить `public/third-party-licenses.txt`            |
| `npm run sbom`           | Список состава (CycloneDX) в `sbom.cdx.json`          |

Решения, которые трудно отменить, записаны в [docs/adr](docs/adr/README.md).
