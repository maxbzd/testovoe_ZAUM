# 0007. Тесты: 100% покрытия, e2e в трёх движках, мутации

## Контекст

Цель — чтобы любое изменение можно было вносить без страха сломать то, что не видно глазами.

## Решение

- Юнит-тесты и тесты интерфейса (Vitest, Testing Library): порог 100% по операторам, веткам, функциям и строкам,
  проверяется в CI. Недостижимые защитные ветки убираются из кода, а не прячутся от отчёта.
- Сквозные тесты (Playwright) в Chrome, Firefox и Safari (WebKit), включая эмуляцию iPhone и Android:
  сценарии, доступность (axe) в обеих темах, отсутствие горизонтальной прокрутки на ширинах 320–1920.
- Мутационные тесты (Stryker) для логики: проверяют, что тесты действительно падают при порче кода.
  Запускаются вручную (`npm run mutation`), потому что занимают около получаса. Результат: 98–99%; оставшиеся мутации эквивалентны
  и помечены в коде комментарием `Stryker disable` с причиной. Мутации массивов исключены (устаревшие замыкания в хуках
  ловит правило `react-hooks/exhaustive-deps`).
- Скриншотные тесты (`npm run test:visual`) защищают внешний вид, но зависят от ОС и шрифтов,
  поэтому в CI не входят.

## Последствия

- 100% покрытия не гарантирует отсутствие ошибок; мутационный балл показывает, насколько тесты строги.
